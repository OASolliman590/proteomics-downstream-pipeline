# Releases and the versioned successor

This guide covers the release tooling of packet R12 (FR-115–FR-120). The current tree is **not a v1.0 release**. No license has been selected, and no publication has been authorized. Both are operator decisions (AGENTS.md); the tooling refuses to stand in for them.

## What a release needs

1. Every release gate re-executed on the exact tree to be released (V119): the full Python and R suites, the spec kit, the R11 lock qualification, and CI on the pushed commit for the cross-platform cases.
2. The Maintainer-only private gates run locally by Omar: V111 (original archive verification) and V114 (full maintained study run). See the [Maintainer runbook](../validation/013-release/MAINTAINER_RUNBOOK.md).
3. A clean hygiene report (`check` below) with no blocking finding.
4. Operator decisions recorded in `docs/validation/013-release/operator-decisions.json`: license, ownership and disclosure review. This file does not exist yet, so a public release is refused (`E_LICENSE_UNRESOLVED`).
5. A release-authorization record for the exact version.

## Hygiene check (V117)

```bash
.venv/bin/python scripts/maintained/build_release.py check
```

The check inventories only **tracked** files. Untracked environments (`.venv/`, `.r-lib/`), runs, data and private evidence never enter a release. A tracked file blocks the release when it is a private workbook or data archive, an environment or credentials file, or private execution output. It also blocks when it contains credential-like text or an absolute private path (a user home or mounted volume; CI runner homes are allowed), when it is a license file with no recorded license decision, or when it is a protected recovered-baseline file whose hash changed. Exit 0 means no finding; exit 2 means blocked, and the JSON lists every finding.

## Versioned successor export (V118)

```bash
.venv/bin/python scripts/maintained/build_release.py export --version 1.0.0 \
  --destination /path/outside/the/repository/release-root --authorization /path/to/authorization.json
```

The authorization record is a JSON object `{"release_authorized": true, "version": "1.0.0", "authorized_by": "...", "scope": "private_successor" | "public"}`; a public scope also needs `license_decision` and the operator decision record. The export refuses when:

| Code | Reason |
|---|---|
| `E_RELEASE_NOT_AUTHORIZED` | no authorization record, or it does not name this version |
| `E_RELEASE_HYGIENE` | the hygiene check has a blocking finding |
| `E_LICENSE_UNRESOLVED` | a public release without a recorded license decision and disclosure review |
| `E_PATH_COLLISION` | the destination already exists (nothing is ever overwritten) |
| `E_RELEASE_DESTINATION` | the destination lies inside the source tree |
| `E_RELEASE_VERSION` | the version is not a semantic version |

On success it writes `<destination>/proteomics-downstream-pipeline-<version>/` with byte-identical copies of the tracked files, `MANIFEST.sha256` and `release.json`, and re-verifies that the protected baseline did not change. The recovered archive package is never touched.
