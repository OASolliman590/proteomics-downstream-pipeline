## Engineering notes

- **Welch engine (R15a).** The Welch statistic and its df are computed from the same log2 observed-cell matrix as limma (SM04: no new imputation). The paired variant uses within-subject differences. A Welch result is never mixed with limma moderation. Adaptations for covariates or blocks are recorded in `eligibility.json` and in the plan decision.
- **Pathway libraries (R15b).** Library files are read only from the declared local path. The manifest hashes are checked before parsing. The ORA universe is the measured mapped eligible set (SM17). Pre-ranked enrichment reuses the existing exploratory fgsea adapter, and its ranks use the SM15 tie-break.
- **Calibration (R15c).** Gates and seeds are written before the first run (see the contract). Null calibration reuses the R14f design (15 versus 15 units, 200 pure-noise features). Planted-signal calibration adds five planted features. Subject-blocked and LOOCV variants reuse the same design factory. Long runs use fold-level checkpointing and L'Ecuyer streams, as in R14d and R11.
- **Multi-study (R15d).** Each study is validated and hashed before it runs. Private inputs and outputs stay under a local, git-ignored run root. Only the non-identifying status record is written under `docs/validation/`. Public downloads are a separate explicit action that reads the approval record and writes outside the repository.
- **Synthetic fixtures.** Every fixture is generated by the synthetic design factory (`tests/fixtures/methods_extension/`). Real study data are never used in automated tests.
- **Gates.** Each V case has an independent oracle written in the test. Record commands, versions, seeds, hashes and exit codes in packet-local evidence. Missing optional software is NOT_RUN.
