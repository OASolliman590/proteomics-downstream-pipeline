## Engineering notes

- **Leakage safety (R14d)** is enforced structurally. Each fold receives a training index and a held-out index. Every transform is a fit/apply pair. A per-fold `transform_audit.jsonl` records which indices fitted each transform; V152 asserts it.
- **Units, not observations.** Resampling, CV folds, permutations and influence use the biological-unit table from the plan (SM03). Repeated designs group folds and permutations by subject.
- **Compute guards.** Nested CV × permutation is expensive. The planner estimates cost from n, p, folds, repeats and B, and refuses beyond the declared guard (E_BIOMARKER_COMPUTE_GUARD) rather than silently reducing B or repeats. Use parallel workers with L'Ecuyer streams and fold-level checkpointing (the R11 cache/resume pattern).
- **Calibration (R11 extension).** Add null-scenario calibration for R14d: nested-CV AUC centred at 0.5, classifier-permutation P uniform, and a deliberately leaky reference showing inflation. Add a dense-cluster versus random-set calibration for the R14e connectivity null. These extend V105-style evidence and are recorded in R14f.
- **Generality matrix (V167)** fixtures are generated by one synthetic design factory reused across packets, so every packet tests the same design cells.
- Use each V case's independent oracle, written directly in the test, before trusting the adapter. Record commands, versions, seeds, hashes and exit codes in packet-local evidence. Missing optional software is NOT_RUN.
